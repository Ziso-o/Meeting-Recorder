# 24/7 무인 운영 가이드 (Windows 네이티브 · Docker 없음)

목표: 회의 녹음 파일을 `data/incoming` 에 넣기만 하면 **항상 켜져 있는** 시스템이
자동으로 회의록을 만들어 `data/out` 에 떨어뜨린다. n8n/Docker 없이 `watch` + Windows
기본 도구(작업 스케줄러)만 사용한다. (B2G 보안환경: 서드파티 서비스 매니저 불필요)

---

## 0. 구성 개념

```
 회의 녹음(.m4a/.mp3/.wav)
      │  (탐색기 드래그&드롭 또는 cp)
      ▼
 data/incoming ──► [watch: 상시 실행] ──► 전사+화자분리+회의록 ──► data/out
                                          └─ 처리한 원본 ──► data/done (실패: data/failed)
```
- **watch** = `python -m minutes.watch` (폴더 감시 무한 루프, 추가 서버 불필요)
- **run_watch.bat** = watch를 감싼 런처(크래시 시 자동 재시작 + 로그)
- **작업 스케줄러** = 부팅 시 run_watch.bat 자동 시작 + 로그인 없이 실행

---

## 1. 사전 준비 (1회)

- [ ] `.env` 파일 생성(아래 2번). ⚠️ 터미널에 붙여넣지 말고 **파일로** 저장.
- [ ] `uv pip install -e ".[transcribe]"` 완료(torch/faster-whisper/pyannote/soundfile).
- [ ] Ollama가 **로그인 시 자동 실행**되는지 확인(트레이 아이콘). `ollama list` 로 모델 확인.
- [ ] **전원 옵션**에서 절전/최대절전 끄기 (24/7이므로):
      제어판 ▸ 전원 옵션 ▸ "다음 시간 후 절전 상태로 전환: 안 함".
      (노트북이면 전원 연결 상태 기준으로 설정)

## 2. `.env` 만들기 (파일로!)

Git Bash에서 메모장으로 열어 저장:
```bash
notepad .env
```
내용(값 뒤 주석 이제 안전하지만, 되도록 값만):
```
OLLAMA_HOST=http://localhost:11434
OLLAMA_MODEL=qwen2.5:7b
ASR_ENGINE=faster-whisper
WHISPER_MODEL=small
DIARIZER=auto
HF_TOKEN=hf_새로_발급한_토큰
```
> `.env` 는 `.gitignore` 로 커밋되지 않는다. HF 토큰은 **새로 발급한 값**을 넣을 것.

## 3. 수동으로 먼저 확인

```bash
# 실오디오 1건 직접 처리(경로는 실제 파일로, Git Bash는 / 사용)
.venv/Scripts/python -m minutes.pipeline --audio ./data/test.m4a --profile secure

# watch 수동 실행 테스트 (다른 창에서 data/incoming에 파일 복사)
.venv/Scripts/python -m minutes.watch --profile secure
```

## 4. 상시 실행 등록 (작업 스케줄러)

### 4-1. 런처 확인
`scripts\run_watch.bat` — 더블클릭하면 watch가 뜨고, 꺼져도 10초 후 자동 재시작.
로그는 `logs\watch.log`.

### 4-2. 작업 스케줄러 등록
1. **작업 스케줄러**(Task Scheduler) 실행 → **작업 만들기**(기본 작업 아님).
2. **일반** 탭:
   - 이름: `MeetingRecorder-Watch`
   - "사용자가 로그온했는지 여부에 관계없이 실행" 선택
   - "가장 높은 수준의 권한으로 실행" 체크
3. **트리거** 탭 ▸ 새로 만들기 ▸ "시작할 때" (부팅 시 자동 실행)
4. **동작** 탭 ▸ 새로 만들기 ▸ 프로그램 시작:
   - 프로그램: `C:\projects\Meeting-Recorder\scripts\run_watch.bat`
   - 시작 위치: `C:\projects\Meeting-Recorder`
5. **설정** 탭:
   - "작업이 실패하면 다시 시작" 체크(예: 1분마다, 3회)
   - "작업을 요청 시 실행 중지 안 함" 등 상시성 옵션 확인
6. 저장(계정 암호 입력). → 재부팅하거나 작업 우클릭 ▸ **실행**.

### 4-3. 동작 확인
```bash
# 로그 실시간 확인 (Git Bash)
tail -f logs/watch.log
# data/incoming 에 오디오 넣고 data/out 에 .minutes.md 생기는지 확인
```

## 5. 운영 팁

- **입력 방법**: `data\incoming` 에 파일을 넣기만 하면 됨(탐색기 드래그&드롭, 네트워크
  공유폴더 매핑, `cp` 등). "업로드" 서버가 따로 없다 — 그냥 폴더에 복사.
- **파일명 규칙**: 이름에 `secure` 포함 시에도 pipeline은 `--profile secure` 고정이라
  전부 로컬 처리. 내부회의를 클라우드로 돌릴 계획이면 watch를 profile별로 2개 띄운다.
- **로그 관리**: `logs\watch.log` 가 커지면 주기적으로 비우거나 로테이션.
- **중지**: 작업 스케줄러에서 작업 **사용 안 함**/**끝내기**. (그냥 창 닫기는 재시작됨)
- **처리 순서**: 크래시로 중단돼도 원본은 incoming에 남아 재시작 시 재처리된다
  (성공분만 done으로 이동).

## 6. n8n 이 꼭 필요할까?

- **로컬 24/7 폴더처리만 목적이면 n8n 불필요** — `watch` 가 그 역할을 이미 한다.
- n8n 이 유리한 경우: 웹훅 트리거, 다단계 분기, 외부 알림(Slack/메일), GUI 모니터링.
- 쓰려면 **Docker 없이 네이티브**로: Node.js LTS + `npm i -g n8n` + `n8n start`.
  단, `workflows/*.json` 은 도커 경로 전제 → **Windows 네이티브용 수정본이 필요**하다.
  (`docs/STACK_MANUAL_TDL.md` §5, §7-b 참조)
