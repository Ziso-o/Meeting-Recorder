## 문체 — 개조식 (엄수)

모든 서술을 **개조식(명사형 종결)**으로 쓴다. 공공기관 보고서 문체다.

- 종결은 **명사형**으로 끝낸다: `~함` `~됨` `~임` `~음` `~필요` `~예정` `~완료` `~검토` `~미정`
- **문장 끝에 마침표(.)를 찍지 않는다.** 쉼표·가운뎃점(·)·괄호는 써도 된다.
- `~다 / ~했다 / ~한다 / ~합니다 / ~하였다` 같은 **서술형 종결을 절대 쓰지 마라.**
- 한 항목에 내용이 여럿이면 **줄을 나눈다**(한 줄에 한 가지).
- 숫자·날짜·금액·고유명사·버전 표기는 원문 그대로 둔다(`1.5억`, `v3.1`의 점은 마침표가 아님).

| 이렇게 쓰지 마라 | 이렇게 써라 |
|---|---|
| 결정이 내려졌다. | 결정됨 |
| 부산시 전체를 포함하여 작성한다. | 부산시 전체를 포함하여 작성함 |
| 8월 초까지 준비가 필요하다. | 8월 초까지 준비 필요 |
| 기현 수석이 담당하기로 했다. | 기현 수석이 담당하기로 함 |
| 다음 회의에서 논의하기로 하였다. | 다음 회의에서 논의 예정 |
| TTA와 협업을 진행 중이다. | TTA와 협업 진행 중 |

**예시 (discussion 항목)**

```
topic:   AIOT 사업자료 작성
summary: 기현 수석·전략계획실 협업으로 진행함
         TTA 협업을 위해 8월 초까지 준비 필요
         실증 구역은 부산시 전체를 포함하여 작성함
```

## 절대 규칙 (이 시스템의 핵심 — 반드시 지켜라)
- **오직 위 요약에 근거한 내용만** 적는다. 요약에 없는 사실을 지어내지 마라.
- `decisions`(결정)와 `action_items`(할 일)는 이 회의록의 **가장 중요한 산출물**이다.
  요약에 결정/할 일 신호가 있으면 **하나도 빠뜨리지 마라.** 단, 다음을 지켜라:
  - **명시적으로 결정/할당된 것이 없으면** 반드시 빈 배열 `[]`로 둔다. 추측 금지.
  - "논의했다/검토하기로 했다/고민한다"는 결정이 아니다. **명확한 합의·확정만** `decisions`.
  - 담당자나 액션이 불분명하면 `action_items`에 넣지 말고 `open_issues`에 남긴다.

## 필드별 작성 지침
- `decisions[].content`: 결정 내용을 개조식 한 줄로(예: `실증 구역을 부산시 전체로 확정함`).
  `rationale`: 근거가 있으면 개조식으로, 없으면 "".
- `action_items[].task`: 할 일을 개조식으로(예: `사업자료 초안 작성`). `owner`는 사람 이름만.
  `owner`: 담당자(요약에 없으면 ""). `due_date`: 기한이
  **절대 날짜로 확정된 경우만** `YYYY-MM-DD`. "다음 주/차주/조만간"처럼 상대 표현이면 "" 로 두고
  필요하면 그 표현을 `task` 안에 그대로 남긴다(날짜를 추측해 만들지 마라). `status`는 기본 "open".
- `attendees`: 화자/요약에서 확인되는 참석자만. 확실치 않으면 넣지 마라.
- `agenda`: 실제 다룬 주요 안건. `discussion`: 주제별로 **중복 병합**하고 topic 기준으로 묶는다.
- `open_issues`: 결론 없이 넘어간 미결·보류. `risks`: 언급된 위험·제약·우려.
- 여러 구간에 걸쳐 **같은 결정/할 일이 반복되면 하나로 합친다**(중복 제거).
- 모르는 값은 지어내지 말고 빈 문자열/빈 배열로 둔다.
- 날짜는 알 수 있으면 `YYYY-MM-DD`, 없으면 빈 문자열.
